# v0.4 Track B — Map Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate valid, reachable dungeon and cave maps from a seed, painted with the existing editor-exact autotile painter, plus reusable "stamps" captured from the user's own maps.

**Architecture:** Generators are pure functions producing a `Layout` (floor mask + rooms + entrance/exit). A *tile profile* maps layout roles (`floor`, `wall`, …) to `TileSpec`s, suggested from tileset data or supplied by the caller. `layoutToPaintOps` turns layout + profile into existing `PaintOp`s; `generate_map` applies them with `applyPaintOps`, verifies reachability against the tileset's real passability flags, and writes once. No bundled map assets.

**Tech Stack:** TypeScript, zod, `node:test`. Reuses `mulberry32` (src/battle.ts), `applyPaintOps`, `PaintOp`, `TileSpec`, `tableType`, `kindDescription` (src/tiles.ts), `loadTileset`, `checkSheetsAvailable` (src/tools/tileTools.ts).

**Spec:** `docs/superpowers/plans/2026-10-24-v0.4-00-overview.md`. Requires Track A tasks A1 (test harness) and A2 (`passableGrid`) merged.

## Global Constraints

- Node `>=18` ubuntu + windows; ESM, strict, NodeNext, `.js` import suffixes.
- Seeded and deterministic: same options + seed → identical output on every platform (use `mulberry32`, never `Math.random`, inside generators).
- Size bounds: map width/height `5–256`; reject anything larger at the zod layer.
- Tools register under profile group `generation` (A3).
- Branch `feat/v0.4-b-generation`.

## Review Focus

1. `generate_map` onto an existing map that already has tiles requires `overwrite: true`, otherwise errors without writing.
2. Tileset where the suggested wall tile is passable (or the floor impassable): `generate_map` fails with an explanatory message and writes nothing.
3. Map smaller than the minimum room size, or a seed that yields a disconnected cave: clear error after bounded retries, never an infinite loop.
4. Stamp names containing `..`, `/`, `\`, `:` or reserved Windows names are rejected before any file access.
5. `place_stamp` partly outside the map bounds is rejected whole, not clipped.

### Task 2 (B2): Dungeon generator

**Files:**
- Create: `src/gen/dungeon.ts`, `test/genDungeon.test.mjs`

**Interfaces:**
- Consumes: B1. Produces: `export interface DungeonOptions { width: number; height: number; seed: number; minRoom?: number /*5*/; maxRoom?: number /*11*/ }`; `export function generateDungeon(opts: DungeonOptions): Layout`; throws `GenError` (`export class GenError extends Error {}` in `src/gen/layout.ts`) when the map cannot hold at least 2 rooms.
- Algorithm: binary space partition until leaves are no larger than `2*maxRoom`; one room per leaf inset by 1 cell; connect sibling subtrees with an L-shaped 1-wide corridor between room centres; `entrance` = centre of the first room, `exit` = `farthestFrom(entrance)`. The outer 1-cell border is always wall.

- [ ] **Step 1: Write failing tests:** `same seed gives identical floor masks`; `different seeds give different masks`; `a 40x30 map has at least 3 rooms`; `every floor cell is reachable from the entrance` (property test over seeds 1–50 and sizes 15–60); `the border ring is never floor`; `entrance and exit are floor cells and differ`; `throws GenError for a 6x6 map with minRoom 5`; `256x256 generates in under 1000 ms`.
- [ ] **Step 2: Run, expect FAIL. Step 3: Implement. Step 4: PASS, commit** `feat: dungeon generator`.

### Task 3 (B3): Cave generator

**Files:**
- Create: `src/gen/cave.ts`, `test/genCave.test.mjs`

**Interfaces:**
- Produces: `export interface CaveOptions { width: number; height: number; seed: number; fillPercent?: number /*45*/; smoothing?: number /*4*/; minFloorRatio?: number /*0.3*/ }`; `export function generateCave(opts: CaveOptions): Layout`.
- Algorithm: random fill at `fillPercent` wall, `smoothing` passes of the 4-5 neighbour rule, keep only the largest connected floor region, border forced to wall. If the floor ratio is below `minFloorRatio`, retry with `seed + 1 … seed + 10`, then throw `GenError`. `entrance` = a floor cell nearest the top-left; `exit` = `farthestFrom(entrance)`; `rooms` = `[]`.

- [ ] **Step 1: Write failing tests:** determinism; `connected for seeds 1–50`; `floor ratio at least minFloorRatio`; `border is wall`; `throws GenError when fillPercent is 95`; `256x256 under 1000 ms`.
- [ ] **Step 2–4: fail, implement, pass, commit** `feat: cave generator`.

### Task 4 (B4): Tile profiles

**Files:**
- Create: `src/tileProfile.ts`, `test/tileProfile.test.mjs`

**Interfaces:**
- Consumes: `TileSpec`, `tableType`, `kindDescription`, `KIND_RANGE`, `sheetBase`, `sheetTileCount` from `src/tiles.ts`; the `MvTileset` shape from `src/tools/tileTools.ts`.
- Produces: `export interface TileProfile { floor: TileSpec; wall: TileSpec; wallTop?: TileSpec; decor?: { tile: TileSpec; weight: number }[] }`; `export const tileProfileSchema` (zod, same shape); `export function suggestTileProfile(tileset: MvTileset): { profile: TileProfile; notes: string[] }`; `export function profileProblems(profile: TileProfile, tileset: MvTileset): string[]`.
- Heuristic (document it in the tool description and in code comments; do not claim it recognises RTP tilesets by name): `floor` = lowest-numbered A2 kind whose flags say passable, else the first passable A5 tile; `wall` = lowest-numbered A4 kind with `tableType(kind) === "wall"` and impassable flags, else the first impassable A5/B tile; `wallTop` = the A4 kind with `tableType === "floor"` in the same pair (verify the pairing against `kindDescription` output for the A4 range before relying on it; if it cannot be determined leave `wallTop` unset). Every choice adds a line to `notes`.
- `profileProblems` reports: sheet has no image assigned; `floor` impassable; `wall` passable.

- [ ] **Step 1: Write failing tests** using a synthetic tileset object (flags array of 8192 zeros with chosen kinds flagged `0xf`, `tilesetNames` with A2/A4/A5/B names): `suggests the first passable A2 kind as floor`; `suggests an impassable A4 wall-table kind as wall`; `falls back to A5 when A2 has no image`; `notes explain each pick`; `profileProblems flags a passable wall`; `profileProblems flags a sheet without an image`; `tileProfileSchema rejects a profile missing floor`.
- [ ] **Step 2–4: fail, implement, pass, commit** `feat: tile profile suggestion`.
