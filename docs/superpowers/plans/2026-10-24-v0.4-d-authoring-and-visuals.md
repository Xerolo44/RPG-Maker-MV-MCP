# v0.4 Track D — Authoring and Visuals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut event authoring from dozens of low-level calls to one (`build_dialogue_tree`, `create_event_from_template`) and give the paint-and-look loop two more views: a passability overlay and a before/after diff image.

**Architecture:** `compileDialogue` and `buildTemplate` are pure functions returning command lists / event pages, validated with `validateCommandList` (Track A2) in their own tests. Tools wrap them and reuse `insertEventCommands` and `DEFAULT_EVENT_PAGE` from `src/tools/mapTools.ts`. Render additions extend `RenderInput` in `src/render.ts` and the existing `render_map_image` tool.

**Tech Stack:** TypeScript, zod (recursive schemas via `z.lazy`), `node:test`.

**Spec:** `docs/superpowers/plans/2026-10-24-v0.4-00-overview.md`. Requires Track A tasks A1 and A2 merged.

## Global Constraints

- Node `>=18` ubuntu + windows; ESM, strict, NodeNext, `.js` import suffixes.
- Every generated command list passes `validateCommandList` and ends with the `{code:0,indent:0,parameters:[]}` terminator.
- Parameter layouts of event commands must be checked against `src/reference.ts` (`EVENT_COMMAND_REFERENCE`) while implementing; where the layouts in this plan disagree with it, the reference wins and the discrepancy is noted in the PR.
- Message boxes hold 4 lines (same rule as `add_dialogue`).
- Tools register under profile groups `authoring` (D1, D2) and `render` (D3, D4).
- Branch `feat/v0.4-d-authoring`.

## Review Focus

1. A `choices` node with zero choices, a `say` with an empty string, or a tree nested more than 8 levels: rejected with a clear message (zod / compile error), never a malformed list.
2. `create_event_from_template` on an occupied or out-of-bounds tile: refuses (occupied needs `allowStack: true`), writes nothing.
3. `render_diff` when the map was resized, created this session (no backup), or the backup file is missing: returns a clear text result rather than throwing.
4. Dialogue text containing MV control codes (`\C[2]`, `\N[1]`) is passed through unchanged, never escaped or split mid-code.
5. `showPassability` on a tileset with missing flags or a map with out-of-range tile ids: no crash, cells treated as walkable.

- Tool: `build_dialogue_tree({ tree, mapId?, eventId?, pageIndex = 0, index?, dryRun = false })` → `{ commands: number, inserted?: …, problems: string[], preview: Cmd[] (only when dryRun, or when ≤ 40 commands) }`. Without `mapId`+`eventId` it behaves as a dry run.

  - `inn`: `{ price: number; greeting?: string }` — greeting, 102 choices `["Stay (<price>G)", "Leave"]` cancel→1; stay branch: 111 gold ≥ price → 125 minus, 221 fade out, 230 wait 30, 314 recover all, 222 fade in, message; else "Not enough gold."

  - `save_point`: `{}` — 352 Open Save Screen.
  - `npc`: `{ lines: string[]; face?: {name: string; index: number}; image?: Image }`.

- Tool: `create_event_from_template({ mapId, x, y, name?, allowStack = false, ...templateParams })` — next free event id, refuses out-of-bounds, refuses an occupied tile unless `allowStack`, one `writeJson`; returns `{ eventId, name, pages: n }`. ### Task 4 (D4): `render_diff`

**Files:**
- Create: `src/mapDiff.ts`, `test/mapDiff.test.mjs`
- Modify: `src/render.ts` (add `outlines: { x: number; y: number; color: Rgb }[]` to `RenderInput`, drawn as a 2 px inner border after markers), `src/tools/renderTools.ts`, `scripts/smoke.mjs`

**Interfaces:**
- Produces: `export interface MapFileLike { width: number; height: number; data: number[]; events: (({id: number; x: number; y: number} & Record<string, unknown>) | null)[] }`; `export interface MapDiff { sizeChanged: boolean; changedCells: Point[]; events: { added: number[]; removed: number[]; moved: number[]; edited: number[] } }`; `export function diffMaps(before: MapFileLike, after: MapFileLike): MapDiff` — a cell is changed if any of its 6 layer values differs; comparison covers the overlapping area when sizes differ (`sizeChanged: true`); an event is `moved` if x/y differ and `edited` if its JSON (excluding x,y) differs.
- Tool `render_diff({ mapId, against?: { session?: string; changeset?: string }, tileSize = 24 })`: default `against` = the most recent backup session (from `project.listBackupSessions()`) that contains `data/Map<NNN>.json`; `changeset` reads `.mcp-backups/changesets/<id>/files/data/Map<NNN>.json` (A5 layout). Output: text summary (counts and the first 30 changed cells / event ids) + a PNG of the current map with changed cells outlined yellow and added/moved events outlined green. When no backup exists: text result saying the map has no earlier version this session (no error).
