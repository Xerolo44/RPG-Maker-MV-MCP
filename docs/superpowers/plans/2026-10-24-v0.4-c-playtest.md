# v0.4 Track C — Scripted Playtests and Event Simulation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an agent run a scripted scenario in the real MV engine (move, interact, advance dialogue, assert on switches / variables / messages, screenshot, record video) on any OS, and simulate a single event offline without any browser.

**Architecture:** `playtest_scenario` drives an installed Chrome/Edge through `playwright-core`, serving the project with the existing static server and injecting a hook script (`window.__mcp`) at page load — nothing is installed into the user's project. Pure parts (assert evaluation, A*, step schema, static path resolution, browser discovery, event interpreter) are unit-tested without a browser. `simulate_event` is a separate pure interpreter over command lists.

**Tech Stack:** TypeScript, zod, `playwright-core` (optional dependency, dynamic import), `node:test`.

**Spec:** `docs/superpowers/plans/2026-10-24-v0.4-00-overview.md`. Requires Track A tasks A1 and A2 merged.

## Global Constraints

- Node `>=18`; CI has no browser and no MV engine files — every browser-dependent test must `skip` itself when `findBrowserExecutable()` returns `null` or `RPGMV_TEST_PROJECT` is unset.
- `playwright-core` is an `optionalDependencies` entry only; the server must start and every other tool must work when it is not installed.
- The injected hook is read-only toward game data except through explicit steps (`setSwitch`, `setVariable`, `teleport`); it never writes project files.
- Static server binds `127.0.0.1` only. Scenario screenshots/videos are written under `<project>/.mcp-playtest/<timestamp>/` and nowhere else.
- Branch `feat/v0.4-c-playtest`.

## Review Focus

1. Scenario with zero steps, or a `moveTo` onto an impassable/unreachable tile: structured failure (`ok:false`, detail text), browser closed, no hang.
2. Total scenario time limit (`timeoutMs`, default 60 000, max 300 000) kills the browser and reports which step was running.
3. Browser or `playwright-core` missing: tool returns an actionable install message; other tools unaffected.
4. Game throws during startup (bad plugin): `errors` contains the message and stack, the scenario fails at step 0.
5. `simulate_event` on a list with unsupported commands, infinite `Loop`, or recursive Common Event: terminates (step limit 10 000, depth limit 8) and reports `ended: "stepLimit"` or the unsupported codes.

### Task 4 (C4): In-page hook

**Files:**
- Create: `src/playtest/hook.ts`

**Interfaces:**
- Produces: `export const HOOK_SOURCE: string` — an IIFE evaluated with `page.addInitScript` that, once `SceneManager`/`$gameMap` exist, defines `window.__mcp` with exactly:
  - `errors: string[]` (from `window.onerror`, `unhandledrejection`, `Graphics.printError`)
  - `messages: string[]` (every line passed to `Game_Message.prototype.add`)
  - `newGame(mapId: number, x: number, y: number): void` — `DataManager.setupNewGame()`, reserve a transfer to the map/position with no fade, `SceneManager.goto(Scene_Map)`
  - `state(switchIds: number[], variableIds: number[]): GameState` — `{ scene: string; mapId: number; x: number; y: number; direction: number; busy: boolean; switches: Record<number, boolean>; variables: Record<number, number> }` where `busy` = `$gameMap.isEventRunning() || $gameMessage.isBusy() || $gamePlayer.isMoving()`
  - `passability(): { width: number; height: number; cells: number[] }` — per cell a bitmask over directions 2 (bit 1), 4 (bit 2), 6 (bit 4), 8 (bit 8) from `$gameMap.isPassable(x, y, d)`; cells occupied by non-through events are treated as blocked
  - `press(name: string, frames: number): void` — sets the key state (the mechanism proven in C1 Step 3) for `frames` frames, then clears it
  - `teleport(mapId, x, y)`, `setSwitch(id, value)`, `setVariable(id, value)`.
- Also export `export interface GameState` (TypeScript mirror of the shape above).

- [ ] **Step 1: Write the hook using the exact mechanisms recorded in C1's Spike results.** No unit test (needs the engine); coverage comes from C6's gated integration test.
- [ ] **Step 2: Build; commit** `feat: in-page playtest hook`.
