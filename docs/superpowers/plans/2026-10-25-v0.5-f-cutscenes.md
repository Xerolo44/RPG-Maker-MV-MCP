# v0.5 Track F — Cutscene and Game-Flow Nodes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend `build_dialogue_tree` so cutscenes, battles, shops and party changes can be written as nested JSON instead of hand-built command lists, and make `lint_events` / `simulate_event` understand the new command shapes.

**Architecture:** New node kinds are added to the existing recursive schema and compiler in `src/dialogueTree.ts` (same one-key-object style as today); the compiler maps each node to the command codes below. Block validation (`src/commandList.ts`) learns Battle Processing (301…604). `src/eventSim.ts` gets a cosmetic no-op set, branch selection for battles and label/jump support.

**Tech Stack:** TypeScript, zod (recursive schemas via `z.lazy`), `node:test`.

**Spec:** `docs/superpowers/plans/2026-10-25-v0.5-00-overview.md`. Builds on `src/dialogueTree.ts` (0.4).

## Global Constraints

- Node `>=18`; ESM, strict, NodeNext, `.js` suffixes. Every compiled list passes `validateCommandList(terminated(list))`; the nesting limit stays `MAX_DIALOGUE_DEPTH = 8` and now also counts battle branch bodies.
- `target` fields accept `"player"` (→ `-1`), `"this"` (→ `0`) or a positive integer event id.
- Defaults are applied by the compiler, not stored in the schema, so the JSON the AI writes stays short.
- All parameter layouts below are from knowledge of the MV engine; verify each against `src/reference.ts`, record discrepancies, and add the missing layouts to `EVENT_COMMAND_REFERENCE` (232 is NOT implemented; do not add it).
- Branch: stay on `release/0.5.0`.

Move-route steps: strings `down`(1) `left`(2) `right`(3) `up`(4) `turnDown`(16) `turnLeft`(17) `turnRight`(18) `turnUp`(19) `walkAnimOn`(31) `walkAnimOff`(32) `stepAnimOn`(33) `stepAnimOff`(34) `dirFixOn`(35) `dirFixOff`(36) `throughOn`(37) `throughOff`(38) `transparentOn`(39) `transparentOff`(40); objects `{jump:{x,y}}`(14, `[x,y]`) `{wait:n}`(15, `[n]`) `{switchOn:id}`(27) `{switchOff:id}`(28) `{speed:1–6}`(29) `{frequency:1–5}`(30). A route command is `{code, parameters, indent: null}`; `moveRoute.list` holds all of them plus a final `{code:0, parameters:[]}`; the `505` rows hold the same route commands WITHOUT the terminator, each as `parameters: [routeCommand]`.

## Review Focus

1. A `moveRoute` with 0 or 101 steps, an unknown step name, `jump` with non-integer coordinates, `speed: 7`: rejected with a clear message and no partial output. [F1]
2. `battle` with `onEscape` but `canEscape: false` (or `onLose` without `canLose`): rejected, never an unreachable branch. [F2]
3. Nesting: a battle branch containing choices containing an `if` — indents and closers exact; depth 9 rejected. [F2]
4. `playAudio` with `name: ""` (stop) and a name containing control characters/newlines: empty allowed, newlines/NUL rejected. [F1]
5. `simulate_event` on a list with `119` pointing to a missing label or a label loop: terminates (`stepLimit` / unsupported note), never throws. [F3]
