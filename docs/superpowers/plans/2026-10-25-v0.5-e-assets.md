# v0.5 Track E — Asset Import and Catalog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an assistant bring images and audio into a project safely (`import_asset`), see what assets exist and which are used (`list_assets`), and look at an image (`preview_asset`).

**Architecture:** Pure format/name validation in `src/assetFormats.ts` (header sniffing, no decoding), catalogue logic in `src/assetCatalog.ts` reusing `collectAssetRefs` from `src/assets.ts`, binary writes through a new `Project.writeBinary`, tools in `src/tools/assetTools.ts` under a new profile group `assets`.

**Tech Stack:** TypeScript, zod, `node:test`. PNG header parsing and a nearest-neighbour downscale are added to `src/png.ts` (no dependencies).

**Spec:** `docs/superpowers/plans/2026-10-25-v0.5-00-overview.md`.

## Global Constraints

- Node `>=18` ubuntu + windows; ESM, strict, NodeNext, `.js` import suffixes.
- Folder set (exact): `img/animations`, `img/battlebacks1`, `img/battlebacks2`, `img/characters`, `img/enemies`, `img/faces`, `img/parallaxes`, `img/pictures`, `img/sv_actors`, `img/sv_enemies`, `img/system`, `img/tilesets`, `img/titles1`, `img/titles2`, `audio/bgm`, `audio/bgs`, `audio/me`, `audio/se`.
- Accepted types by magic bytes only (never by extension): PNG (8-byte signature), Ogg (`OggS` at offset 0), M4A (`ftyp` at offset 4). Image folders accept PNG only; audio folders accept Ogg or M4A only.
- Size caps: images 32 MiB, audio 128 MiB. Name rule: `/^[A-Za-z0-9!$][A-Za-z0-9 _!$()-]{0,63}$/`, no trailing space, not a Windows reserved device name (CON, PRN, AUX, NUL, COM1–9, LPT1–9, case-insensitive). The extension is chosen from the detected type (`.png`, `.ogg`, `.m4a`), never taken from user input.
- New profile group name: `assets`. Branch: stay on `release/0.5.0`.

## Review Focus

1. Source path that is a directory, a symlink, a UNC path (`\\server\share\x.png`), a device path (`\\.\COM1`), a relative path, a 0-byte file or a file whose extension lies about its content: refused with a clear message, nothing written. [E2]
2. Name collisions that differ only by letter case (`Hero` vs `hero` on a case-insensitive filesystem): treated as existing; replacing needs `overwrite: true`. [E2]
3. `import_asset` inside an open changeset: refused (binary content cannot be staged); the project is unchanged. [E2]
4. A folder with thousands of files or a 100 MB audio file: `list_assets` reads only file headers, never whole files, and caps its output. [E3]
5. A corrupt or interlaced PNG in `preview_asset`: clear error, no crash. [E3]

### Task 1 (E1): Asset formats and PNG header helpers

**Files:**
- Create: `src/assetFormats.ts`, `test/assetFormats.test.mjs`
- Modify: `src/png.ts` (add `pngInfo`, `scaleDownNearest`), `test/png.test.mjs` (create if no PNG test file exists)

**Interfaces:**
- Produces from `src/png.ts`: `export function pngInfo(buf: Buffer): { width: number; height: number }` (header only: signature + first chunk must be IHDR with length 13; throws `PngError`); `export function scaleDownNearest(b: Bitmap, maxEdge: number): Bitmap` (returns `b` itself when both edges ≤ `maxEdge`; otherwise nearest-neighbour scale so the longer edge equals `maxEdge`, keeping aspect, minimum 1 px).
- Produces from `src/assetFormats.ts`:
  - `export const ASSET_FOLDERS: readonly [...]` (the 18 folders above, in that order), `export type AssetFolder`, `export function isAssetFolder(v: string): v is AssetFolder`, `export function isImageFolder(f: AssetFolder): boolean`.
  - `export function validateAssetName(name: string): string` — returns the name or throws `ProjectError` (rules above).
  - `export type AssetType = "png" | "ogg" | "m4a"`; `export function detectAssetType(head: Buffer): AssetType | null`.
  - `export interface AssetInfo { type: AssetType; bytes: number; width?: number; height?: number; warnings: string[] }`; `export function inspectAsset(folder: AssetFolder, name: string, head: Buffer, totalBytes: number): AssetInfo` — `head` is at least the first 64 bytes (or the whole file); throws `ProjectError` when the type does not fit the folder or `totalBytes` exceeds the cap; never reads past `head`.
  - Warnings (strings, advisory only): characters — name starts with `$` → width%3 and height%4 must be 0, otherwise width%12 and height%8; faces — width and height multiples of 144 (recommended 576×288); sv_actors — width%9 and height%6; tilesets — width must be 768 or 384; animations — width%192; titles1/titles2/battlebacks1/battlebacks2 — smaller than 816×624; audio — none (the "other format missing" hint is added by the tools, which can see the folder).

### Task 2 (E2): `Project.writeBinary`, group `assets`, `import_asset`

**Files:**
- Create: `src/tools/assetTools.ts`, `test/importAsset.test.mjs`
- Modify: `src/project.ts` (add `writeBinary`), `src/profiles.ts` (add `"assets"` to `GROUPS`), `src/index.ts` (register under `enabled.has("assets")`), `test/profiles.test.mjs` and any test that enumerates groups, `scripts/smoke.mjs`

**Interfaces:**
- Consumes: E1 (`ASSET_FOLDERS`, `isAssetFolder`, `validateAssetName`, `detectAssetType`, `inspectAsset`).
- Produces: `Project.writeBinary(filePath: string, data: Buffer): Promise<void>` — same guards as `writeText` (`assertIdle`, `assertRolledBack`, path must stay inside the project root), throws `ProjectError("Importing binary files is not supported while a changeset is open. Commit or discard the changeset first.")` when a changeset is active, otherwise `backup`, `mkdir -p`, write, `recordWrite`.
- Tool `import_asset({ source: string, folder: AssetFolder, name?: string, overwrite?: boolean = false })` (group `assets`, exported `registerAssetTools(server, project)` in `assetTools.ts`). `source` must be an absolute local path to a regular file: reject relative paths, UNC (`\\…`) and device (`\\.\…`, `\\?\…`) prefixes, directories, empty files and files above the cap (checked with `stat` BEFORE reading). Name defaults to the source's file name without extension (also validated). Existence check is case-insensitive over the destination folder listing (any extension of the same type family counts for audio only when the same extension). Output `{ imported: { path (project-relative, forward slashes), type, bytes, width?, height? }, replaced: boolean, warnings: string[] }`; for audio add a warning when the other format (ogg/m4a) is missing (`MV's web build needs both`).

### Task 3 (E3): `list_assets` and `preview_asset`

**Files:**
- Create: `src/assetCatalog.ts`, `test/assetCatalog.test.mjs`
- Modify: `src/tools/assetTools.ts`, `scripts/smoke.mjs`

**Interfaces:**
- Consumes: E1; `collectAssetRefs`, `AssetRef` from `src/assets.ts`; `decodePng`, `encodePng`, `scaleDownNearest` from `src/png.ts`.
- Produces: `export interface AssetEntry { name: string; ext: string; bytes: number; width?: number; height?: number; usedBy?: string[] /* at most 3 sources */; unused?: boolean; warnings: string[] }`; `export async function listAssets(project: Project, opts: { folder?: AssetFolder; includeUsage: boolean; limit: number }): Promise<{ folders: { folder: AssetFolder; total: number; files: AssetEntry[] }[]; truncated: number }>` — files sorted by name; per folder at most `limit` entries (the rest counted in `truncated`); reads only the first 64 bytes of each file (`fs.open` + `read`); skips non-files and files with an extension other than the folder's family; `unused` is only set for folders that `collectAssetRefs` covers (not `img/system`, `img/animations`) and only when `includeUsage` is true; usage matching is case-sensitive on `name`.
- Tools: `list_assets({ folder?: AssetFolder, includeUsage: boolean = true, limit: number = 200 /* 1–1000 */ })`; `preview_asset({ folder: image folder, name: string, maxSize: number = 512 /* 32–1024 */ })` returning a text block (`WxH px, <bytes>`; for `img/characters` the sheet layout implied by the name; for faces the grid) and an `image/png` content block scaled with `scaleDownNearest`. `name` is validated with `validateAssetName` and must match an existing file (exact name in the folder listing); files above 32 MiB or undecodable PNGs give a `ProjectError`.
