# RPG Maker MV MCP v0.4 — Overview, Scope and Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement the track plans task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This file is the **spec** the four track plans argue from; read it first.

**Goal:** Ship 0.4.0: safe multi-file editing, project analysis, procedural map generation, a cross-platform scripted playtest runner, and faster event authoring — on top of 0.3.

**Architecture:** Four independent tracks, each its own branch and PR into `main`, built after 0.3 is merged. Track A lands first (test harness + shared utilities); B, C, D then run in parallel. All new tools follow the existing pattern: pure logic in `src/*.ts` (unit-tested against compiled `dist/`), thin zod-validated registration in `src/tools/*Tools.ts`, one end-to-end check in `scripts/smoke.mjs`.

**Tech Stack:** TypeScript (strict, NodeNext ESM), `@modelcontextprotocol/sdk`, zod, Node's built-in `node:test`. One new *optional* dependency: `playwright-core` (Track C only).

## Explicitly NOT in 0.4 (deferred to 0.5)

`analyze_progression` (soft-lock / reachability graph), `render_dialogue`, village and overworld generators, lock-and-key dungeon mode, first-class MZ support, agent eval suite, tile rotate/mirror in stamps, playtest fast-forward, a live in-game bridge. Do not add them to a 0.4 task.

## Global Constraints

Copied from the repository as of 0.3 work-in-progress; every task inherits them.

- Node `>=18`; CI matrix is Node 18.x and 20.x on ubuntu-latest and windows-latest and runs `npm run test`. Nothing may require a browser, an RPG Maker install, or a glob argument to `node --test`.
- `"type": "module"`; TypeScript `strict`, `module`/`moduleResolution` `NodeNext`; relative imports end in `.js`.
- Tool registration shape: `server.registerTool(name, { title, description, inputSchema: { ...zod } }, safe(async (args) => textResult(...)))` from `src/util.ts`. Tool descriptions are written for an AI reader: parameter semantics, MV quirks, pointers to related tools.
- Every project-file write goes through `Project.writeJson` (it snapshots to `.mcp-backups/<session>/` first). After A5, non-JSON writes go through `Project.writeText`.
- MV database arrays are 1-indexed with `null` at index 0; map `events` likewise.
- Event command lists end with `{code: 0, indent: 0, parameters: []}`.
- Version bump at release: `package.json`, `src/index.ts` (`McpServer` version), `server.json` (top-level `version` and `packages[0].version`) → `0.4.0`.
- Only MV is regularly tested; MZ projects are accepted but unsupported. New tools must not corrupt an MZ project but need no MZ-specific behaviour.
- New runtime dependencies: none, except `playwright-core` as an `optionalDependency` (Track C).
- Branch names: `feat/v0.4-a-foundation`, `feat/v0.4-b-generation`, `feat/v0.4-c-playtest`, `feat/v0.4-d-authoring`. Never commit to `main`. Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

Failure modes the spec implies but no single task owns. Each line has a test in the track named in brackets.

1. **No project selected:** every new tool must return the standard `No project selected…` error, not throw out of the handler. [A7, B6, B7, C6, C7, D3, D4]
2. **Map files with `events: [null]`, missing `events`, or `null` holes in the middle:** analysis, stamps, lint and templates must skip nulls. [A6, A7, B7, D4]
3. **User-supplied names reaching the filesystem** (stamp names, scenario screenshot names, `..` segments, absolute paths, Windows reserved characters): rejected, never joined. [B7, C6]
4. **Process killed mid-commit leaves `*.mcp-tmp` files:** next `set_project` removes them and never leaves a half-applied changeset. [A5]
5. **Large inputs:** a 256×256 generated map finishes in under one second; a 5 000-event project lints without stalling; zod `max` bounds on all size parameters. [B2, B3, A7]
